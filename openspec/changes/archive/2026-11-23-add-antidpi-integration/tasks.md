## 8. Remediation (review findings)

- [x] 8.1 Relocating grant: pipe stdin explicitly, verify both destinations' prior identities, stage and length-check each payload, publish atomically per file, emit helper identity before anti-DPI identity, and leave existing privileged binaries intact on any failure.
- [x] 8.2 Non-root rule lifecycle: install nftables tables through the helper's netlink client, write the ownership journal ahead of every mutation, recover only a dead same-epoch owner, refuse a live foreign owner and an unowned table, and keep the journal plus the manager's obligation on any removal failure.
- [x] 8.3 Truthful startup: validate strategies and the hostlist in `install-rules` before the backend spawn, require the engine readiness line after the queue bind, and distinguish a pre-ready startup failure from a later unexpected exit.
- [x] 8.4 Helper execution: resolve `$PATH` to an absolute executable, spawn the resolved path for install, remove, and engine, and stop mutating the process environment.
- [x] 8.5 Capability checks: require effective and permitted bits for both anti-DPI capabilities, and surface the anti-DPI helper in the TUN page's shared capability row so the grant action is reachable when only it is broken.
- [x] 8.6 Persistence and UI: refuse invalid anti-DPI values before any write or migration writeback, report one accurate localized editor error, and state the actual port-443 TLS/QUIC coverage.
- [x] 8.7 Packaging: pre-validate the whole archive before the first prefix write with a version-aware helper set, verify revocation independently of command success, use crate-relative Debian asset paths, and compile staged catalogs from `.po`.
- [x] 8.8 Gates: run the non-root rule lifecycle in a disposable VM with the packaged privilege layout, the grant/upgrade matrix in a disposable filesystem, the GTK repair/restart paths under Xvfb, and the full artifact checks (`make check`, `make test`, `make test-installers`, both Arch recipes, the Debian asset set, AppImage relocation, and a valid older tarball). Kernel-level nftables proof is unverified until 8.8 runs. Ran on an Arch VM (KVM, packaged privilege layout) plus a Debian trixie container for release artifacts. Non-root, as uid 1001 with the packaged helper: both `v2ray_rs_1001` families installed under the hooks with queue 2200; a second controller with its own journal was refused with unchanged tables; `remove-rules --sweep` from another network namespace was refused; owner removal restored the empty ruleset. An injected IPv6 table at the v4→v6 transition left a durable `phase=cleaning` journal (`ipv4=false, ipv6=true`), and the retry after release cleared it. A real dead-owner recovery (install owned by a killed process, then a new controller) replaced the session and cleaned up. The lifecycle harness passed bad-strategy, missing-hostlist, occupied-queue and success-lifecycle; the in-process crash simulation cannot express owner death, so controller-death was proved separately with the real helper. The `v2ray_rs_<euid>` kernel rules decode through `nft -j` as `meta mark & 0x40000000 == 0x40000000` and `ct ... packets 1-12` (this gate found and fixed a data-register endianness defect that had produced mask 64 and packet bounds 1e16).
