## ADDED Requirements

### Requirement: Download GeoIP and GeoSite databases
The system SHALL download GeoIP and GeoSite databases from upstream sources (v2fly GitHub releases for v2ray/xray, SagerNet releases for sing-box).

#### Scenario: Initial download
- **WHEN** the app launches and no geodata files exist locally
- **THEN** the system SHALL download the appropriate geodata files for the selected backend

#### Scenario: Download failure
- **WHEN** the geodata download fails due to network error
- **THEN** the system SHALL report the error and allow the app to function without geodata (GeoIP/GeoSite rules will be non-functional)

### Requirement: Auto-update geodata
The system SHALL use the persisted geodata refresh settings to perform background refreshes while the app is running.

#### Scenario: Startup refresh when data is missing
- **WHEN** the app starts and the selected backend has no local geodata
- **THEN** the app SHALL attempt a background download and reindex pass without blocking startup

#### Scenario: Scheduled refresh while running
- **WHEN** `auto_update_geodata` is enabled and the configured interval elapses
- **THEN** the app SHALL check for updates and rebuild the index if new files arrive or the index is missing

### Requirement: Backend-specific geodata format
The system SHALL download the correct geodata format for the selected backend.

#### Scenario: v2ray/xray geodata
- **WHEN** v2ray or xray is the selected backend
- **THEN** the system SHALL use .dat format files (geoip.dat, geosite.dat)

#### Scenario: sing-box geodata
- **WHEN** sing-box is the selected backend
- **THEN** the system SHALL use .db format files (geoip.db, geosite.db)

### Requirement: GeoData UI Management
The system SHALL provide a Preferences UI for manual geodata refresh that shows last successful refresh time and indexed tag counts for the current backend.

#### Scenario: Manual refresh success
- **WHEN** the user clicks "Update Now" in the GeoData preferences section
- **THEN** the system downloads geodata for the current backend, rebuilds the autocomplete index, and updates the displayed refresh time and tag counts

#### Scenario: Manual refresh failure preserves previous index
- **WHEN** manual refresh or reindex fails
- **THEN** the previous index and displayed metadata remain available and the app reports the failure

### Requirement: Geodata files live in the cache directory
The system SHALL place downloaded geodata files and the geodata index under the active profile's `cache_dir`, so that geodata can be regenerated by deleting the cache without touching user-authored data.

#### Scenario: Geodata downloads land in cache_dir
- **WHEN** the system downloads `geoip.dat`/`geosite.dat` (or `.db` files for sing-box)
- **THEN** the files SHALL be written under `cache_dir/geodata/` and SHALL NOT appear under `data_dir`

#### Scenario: Geodata index lives in cache_dir
- **WHEN** the geodata index is rebuilt
- **THEN** the index SHALL be written under `cache_dir/geodata-index/`

#### Scenario: Geodata is profile-isolated
- **WHEN** the same user runs the binary first with `--profile production` and then with `--profile development`
- **THEN** each profile SHALL maintain its own copy of the geodata files and index
